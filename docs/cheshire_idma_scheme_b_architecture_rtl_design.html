01 / OVERVIEW

设计范围与核心决策

方案 B = 每 Tile 只做一轮 MMIO 配置，提交时硬件形成不可变的 idma_nd_req_t，经 Job FIFO 和 Scheduler 交给多个独立的 iDMA ND Midend + AXI Backend 执行。没有第二次 DMA MMIO 编程。
N独立 Cheshire Tile / CSR 上下文
M共享 DMA Engine / AXI Master
1全局 DDR 控制器
0执行端重复 MMIO 配置

实现约定（2026-10-12 修订）

  • NumTiles 和 NumDmas 为独立的综合/elaboration 参数，默认 4×2，支持单路和非二次幂数量，并非运行时热插拔。
  • 每 Tile 一个 CVA6 和私有资源；DMA 仅访问配置的全局 DDR 范围。
  • 各 Tile 使用相同的本地 MMIO 地址 0x0100_0000，按物理端口隔离 CSR。
  • 每 Tile 和每 Engine 最多一个执行中顶层 ND Job；同 Tile 可排队并按序完成，不同 Tile 并行且可乱序完成。
  • Tile、Pool、Fabric 使用统一时钟及协调复位。独立热复位、自动取消、超时回收不在首版范围。
  • 使用 B2 CSR 和 sw/include/shared_dma.h；不兼容旧 NEXT_ID 读触发驱动。
实际源码：hw/shared_dma/ 包含 CSR、Scheduler、Engine、Pool、DDR Fabric、Subsystem、配置包及 multi_tile_top.sv；target/sim/src/tb_shared_dma.sv 与 util/run_shared_dma_tests.sh 为自校验仿真入口。下文接口草案解释原理，实际端口以这些源码为准。
请区分“软件配置一次”与“只发一次 MMIO 事务”。CPU 仍可能写 SRC、DST、LEN、CONF、Stride、Reps 等多个寄存器；这些写操作只有一轮。CPU 触发 Submit 后，Scheduler → ND Midend 走硬件 valid/ready，不是第二轮寄存器写入。
02 / TOPOLOGY

推荐顶层结构及两张互连网络

控制网络与数据网络完全分开

网络主设备 → 从设备性质是否共享带宽
DMA 控制网络每个 `cheshire_soc.axi_ext_slv_req_o[i]` → 对应 CSR Bank32-bit MMIO 配置；Job 控制、完成读取每 Tile 私有控制入口
Job 分发网络N 个 Job FIFO → Scheduler → M 个 Engine`idma_nd_req_t` + Owner 元数据，valid/ready共享调度资源
DDR 数据网络N 个 Tile DDR Master + M 个 DMA AXI Master → DDRAXI AR/R + AW/W/B，正常 DDR 流量所有参与者共享 DDR 吞吐

每个 CPU 的 MMIO 写入不会直接交给同一个原始 DMA 寄存器组，而是写入由物理端口识别的 CSR Bank[i]。不同 Tile 的多次写入即使交错，也不会覆盖彼此的 SRC/DST/LEN。

Cheshire 现有接口如何复用

`cheshire_soc` 接口在方案 B 中的用途是否需要新加 Tile AXI 接口

推荐 Tile 配置

systemverilog// 参数字段示意；应在配置对象初始化后赋值
TileCfg.NumCores         = 1;
TileCfg.Dma              = 0;  // Tile 内不产生原始 iDMA
TileCfg.AxiExtNumSlv     = 1;  // 向 Tile 外部 CSR 发 MMIO
TileCfg.AxiExtNumRules   = 1;
TileCfg.AxiExtRegionIdx[0]   = 0;
TileCfg.AxiExtRegionStart[0] = 64'h0000_0000_0100_0000;
TileCfg.AxiExtRegionEnd[0]   = 64'h0000_0000_0100_1000;

上述外部地址映射遵循 `gen_axi_out()`：当 Cfg.Dma=1 时内部 DMA 占用 0x0100_0000–0x0100_1000，关闭后可经 AxiExtRegion* 将同一段地址指向外部 CSR。axi_llc_mst_req_o 必须由 LLC/Bypass 路径正确接出。

注意地址域：四个 Tile 内相同 MMIO 地址通过不同的物理控制端口映射到四份 CSR。它们并非一个全局唯一物理 AXI 地址上的单一寄存器组。Tile 私有程序地址也应继续在各 Tile 内部独立解码。
05 / MMIO REGISTERS

每 Tile MMIO CSR：兼容模式与推荐模式

原版 iDMA v0.6.3 的关键寄存器

相对偏移寄存器访问意义
0x000CONFR/W解耦、Burst 控制、ENABLE_ND；保留旧布局
0x004STATUS_0RO当前流状态（后续可扩展成 Pool 状态）
0x044NEXT_ID_0原版读触发若兼容旧驱动，读取时提交 Job
0x084DONE_ID_0RO旧版累计完成序号；跨 Engine 乱序需按序修复
0x0D0 / 0x0D4DST_ADDR LOW/HIGHR/W64 位目的地址
0x0D8 / 0x0DCSRC_ADDR LOW/HIGHR/W64 位源地址
0x0E0 / 0x0E4LENGTH LOW/HIGHR/W传输长度；当前 Backend 集成有效宽度需限制为 32bit
0x0E8 / 0x0ECDST_STRIDE_2 LOW/HIGHR/W二维目标地址步长
0x0F0 / 0x0F4SRC_STRIDE_2 LOW/HIGHR/W二维源地址步长
0x0F8 / 0x0FCREPS_2 LOW/HIGHR/W二维重复次数

生成头文件：`sw/include/regs/idma.h`。该头文件也声明 16 个 STATUS_n / NEXT_ID_n / DONE_ID_n 槽位；但当前 Cheshire NumStreams=1，实际使用的是第 0 路。

方式 B1｜保留原版 MMIO 兼容

每 Tile 放一份 idma_reg64_2d(NumRegs=1)，把它的 idma_nd_req_t + valid/ready 接外部 Job FIFO；NEXT_ID 读触发；每 Tile 新增独立的 next_id / done_id 维护逻辑。

优点：旧驱动改动小。风险：读触发副作用、满队列反压、完成顺序对接复杂，必须逐项验证。

方式 B2｜自定义 Pool CSR（推荐正式版）

仍只在每 Tile 配置一次 MMIO；新增写触发 SUBMIT、队列容量、Completion；由 dma_tile_csr 直接构造 idma_nd_req_t。

优点：状态语义清晰，支持错误和乱序完成。代价：需要适配新的驱动。

已实现的 B2 Pool CSR（新增接口）

偏移寄存器语义
0x100POOL_SUBMIT (W)byte0有效且bit0=1：快照、分配ID、入队、预留完成容量；满或非法立即SLVERR，ID不变
0x104POOL_Q_STATUS (R)bit0=可接受；[15:8]=已提交但未POP数量；[23:16]=剩余完成容量，不是Job FIFO occupancy
0x108POOL_COMP_VALID (R)bit0=当前Tile完成队首有效
0x10CPOOL_COMP_JOB_ID (R)32-bit ID，保持至POP；首笔ID=1，允许自然回绕
0x110POOL_COMP_STATUS (R)[7:0]=0成功/1读错误/2写错误/3内部非法；[31:16]=Engine ID
0x114POOL_COMP_POP (W)byte0有效且bit0=1：消费队首并归还容量；空队列无副作用
0x118POOL_IRQ_ENABLE (R/W)bit0=完成队列非空时的电平IRQ使能
0x11CPOOL_LAST_JOB_ID (R)最近成功提交ID；失败不改变
0x120POOL_SUBMIT_STATUS (R)[7:0]=最近提交结果：0成功/3参数非法/4容量不足
修正阻塞提交死锁：完成容量耗尽时，CPU仍须读Completion并POP，因此SUBMIT不得无限等待。驱动先检查Q_STATUS；容量不足由软件重试。同Tile多个提交者须对检查、配置、SUBMIT及取ID整个序列互斥。非法裸MMIO提交产生SLVERR，CPU如何上报取决于适配器及异常路径；驱动还须检查SUBMIT_STATUS，不能仅依赖CPU异常。

建议在 POOL_SUBMIT 的写响应完成时，确保 Job 已入 FIFO 且完成容量已被预留；LAST_JOB_ID 可供单 CPU 顺序提交后读取。若同一 Tile 内增加多个并发软件提交者，则需再提供事务化分配接口或软件互斥。

06 / ATOMIC JOB

MMIO 到 Job：原子化配置快照

CSR Bank 中的 SRC/DST/LENGTH 等属于可修改的 Shadow Registers。每次提交必须把整套参数原子复制为不可变 tagged_job_t。之后 CPU 可以写下一笔参数，旧 Job 完全不受影响。

systemverilog// 公共类型包中的示意声明；具体 typedef 由同版本宏生成
localparam int TileIdW = (NumTiles > 1) ? $clog2(NumTiles) : 1;
localparam int DmaIdW  = (NumDmas  > 1) ? $clog2(NumDmas)  : 1;

typedef struct packed {
  logic [TileIdW-1:0] tile_id;  // 来源于物理输入端口
  logic [31:0]        job_id;   // 本 Tile 独立分配
  idma_nd_req_t       nd_req;   // 原版 iDMA 多维请求结构
} tagged_job_t;

typedef struct packed {
  logic [31:0]        job_id;
  logic [DmaIdW-1:0]  engine_id;
  logic               error;
  logic [7:0]         error_code;
} completion_t;

新的 CSR→ND 转换函数至少要构造：burst_req.src_addr、dst_addr、length、AXI Burst/Cache/Protocol 及 Backend 选项；二维时还有 d_req[0].reps、src_strides 和 dst_strides。这些字段与 原版生成前端的转换逻辑 对照实现，不能只填地址和长度而放任其他字段为未定义值。

提交原子性要求

条件动作禁止行为
参数有效、Job FIFO与完成容量足够快照入队、分配ID、预留完成容量重复入队或仅分配ID未入队
FIFO或完成容量满立即SLVERR，SUBMIT_STATUS=4无限阻塞或静默丢Job
参数非法SLVERR，SUBMIT_STATUS=3，不分配ID或完成事件截断高位后继续执行
提交后修改Shadow旧Job快照不变修改队列任务

参数校验：长度及二维重复数非零；长度、二维stride/reps高32位为0；地址不得超AXI宽度。128-bit中间算术计算整个二维包围范围，须完全位于[MemStart, MemEnd)，源/目的范围不能重叠。stride无符号，可为0；保守范围检查可能拒绝不相交的交错二维行。一维CONF.ENABLE_ND=0时归一化REPS=1。

必须特别处理低/高 32 位配置写：CPU 先写 LOW 再写 HIGH（或者反过来）在提交前均可；Submit 前才统一取快照。使用设备属性、访问排序和 fence iorw, iorw 等保证参数在提交前可见。
07 / SCHEDULER

N → M Scheduler：任务级仲裁而不是寄存器级仲裁

调度单元的唯一输入是完整 Job

systemverilog// 逻辑握手约定（不是可直接综合的完整 Scheduler）
input  tagged_job_t [NumTiles-1:0] tile_job_i;
input  logic        [NumTiles-1:0] tile_job_valid_i;
output logic        [NumTiles-1:0] tile_job_ready_o;

output tagged_job_t [NumDmas-1:0]  engine_job_o;
output logic        [NumDmas-1:0] engine_job_valid_o;
input  logic        [NumDmas-1:0] engine_job_ready_i;

已实现调度策略

  1. 筛选非空且无执行中Job的Tile。
  2. Tile和空闲Engine均独立RR，每周期最多dispatch一笔。
  3. Engine ready来自寄存的IDLE状态；内部grant仅发往ready Engine，握手、锁存和FIFO pop同时完成。此接口不是可任意反压的通用流仲裁器。
  4. Engine持有(tile_id, job_id)至Completion入队后释放。统一复位首版不使用generation。
systemverilog// 单周期抽象：一笔任务的接纳必须同时完成两件事
assign dispatch_fire[d] = engine_job_valid_o[d] && engine_job_ready_i[d];

// dispatch_fire[d] 时：
// 1) 弹出被选中的 tile_job_fifo
// 2) 写入 engine_owner[d]
// 3) engine_wrap[d] 锁存完整 job
// 不能出现 pop 发生了但 Engine 没有锁存的情况
不要把 Backend 的 `req_ready` 直接等同于顶层 Engine 空闲。后端可能在已有 Job 仍未完成时继续接受 1D 子请求；Engine 只能在完整顶层 ND Response 被处理后释放。

公平性与次序

默认选择轮询 RR。为降低第一阶段复杂度，可加 tile_inflight[i]，令同一 Tile 最多有一个执行中的 Job；这仍允许不同 Tile 在不同 DMA 并行。后续如放开同一 Tile 多 Engine 并发，就必须处理跨 Engine 乱序完成。

08 / ENGINE

Engine Wrapper：ND 握手与任务生命周期

每个 Engine 拥有自己的 Holding Register、ND Midend、Backend 和 AXI RW Join。Scheduler 把完整 Job 分配到 Engine 后，必须保持 Job 不变，直到该 Midend 处理完所有 1D 子请求。

systemverilog// 原始 idma_nd_midend.sv 的关键握手（v0.6.3）
assign nd_req_ready_o = last & nd_req_valid_i & burst_req_ready_i;

// 注意：该 ready 在最后一个 1D 子请求成功交付时才为真。
// 它不是「第一个周期立即收到了完整 ND Job」。
状态行为可否接收下一个顶层 Job
IDLE等待 Scheduler；锁存一笔完整 Job 及 Owner可以（仅在有效握手时）
EXPAND保持 `nd_req_valid=1`、`nd_req_i=hold_q.nd_req` 稳定，等待最终 ND 请求握手不可以
WAIT_DONE全部 1D 子请求已送给 Backend，但数据仍可能在搬运不可以
REPORT握手或排队完成记录；释放 Owner 之前须确保 Completion 不丢失不可以
IDLE归属完成关闭后才能分配下一笔 Job可以
systemverilog// 关键控制片段：示意 RTL，需处理同周期 req/rsp 与复位
assign nd_req_i       = job_hold_q.nd_req;
assign nd_req_valid_i = (state_q == EXPAND);

wire nd_req_fire = nd_req_valid_i && nd_req_ready_o;
wire nd_rsp_fire = nd_rsp_valid_o && nd_rsp_ready_i;

// Job 存放于 holding register；直到 nd_req_fire 保持稳定。
// 完成只能看 nd_rsp_fire，不能用 nd_req_fire 替代。
// 若非法/零重复请求导致「req_fire + rsp_fire 同周期」，也必须记录 Completion。
响应边界特别重要：原版 ND Midend 以 Backend 响应的 last 产生顶层 nd_rsp_valid_o；零重复的异常路径可能在输入完成握手附近立即返回错误响应。不能在状态机的 EXPAND 阶段忽略 nd_rsp_valid_o。

对于每个 Engine，继续原样使用 idma_backend_rw_axi 的内部缓存、Legalizer、AXI Read/Write Pipeline、AXI Burst 拆分；无须让 Backend 理解 tile_id 和 job_id。

09 / MULTIDIM

二维、多维 Job 如何展开及完成

一个有效 2D Job → REPS₂ 个 1D 子请求 → 每个 1D 请求可能由 Backend 产生若干 AXI Burst → 整个 ND Job 完成时对上游只报告一次顶层 Completion。

示例：源行距与目标行距不同

字段设定
SRC0x8000_0000
DST0x9000_0000
LENGTH64 bytes / 每行
REPS_24
SRC_STRIDE_2128 bytes
DST_STRIDE_2256 bytes
1D 子请求序号SRCDST长度
00x8000_00000x9000_000064 B
10x8000_00800x9000_010064 B
20x8000_01000x9000_020064 B
30x8000_01800x9000_030064 B

总传输量为 64 × 4 = 256 bytes。四个 1D 子请求仍属于同一 Job，不应由外层 Scheduler 分到不同 Engine。iDMA `idma_nd_midend.sv` 用 d_req[0] 的 repetitions 和 stride 更新地址，并在最后一个请求上标记 opt.last。

零重复/零长度：提交前拒绝零长度及启用二维时的零重复；一维模式归一化REPS=1。上游ND零重复错误路径不用于正常提交。
10 / COMPLETION

Completion 路由、乱序、信用额与复位

完成归属

Engine保存(tile_id, job_id)；Engine ID为实例编号。最终ND响应到来后进入REPORT，完成入队后才释放Owner。同Tile最多一个执行中Job，因此不同Engine不会同时竞争同一Tile完成入口。统一复位首版不使用generation。

systemverilog// Owner / Completion 示例（不修改 idma_backend_rw_axi）
engine_owner[1] = '{tile_id: 2, job_id: 15};

// Engine1 完成后：
completion_fifo[2].push('{job_id: 15, engine_id: 1,
                          error: engine_rsp.error,
                          error_code: mapped_error_code});

两种完成语义

方案完成上报规则限制
新 Completion FIFO（首选）每次完成送 `(job_id, status, engine_id)`；可乱序CPU 要按 Job ID 匹配，不是单一 done_id
兼容旧 `DONE_ID`每 Tile 只推进连续完成的 Job 编号需要 per-Tile reorder buffer 或保证同 Tile 顺序执行

信用额、复位和错误边界

  • 不变量：排队 + 执行/待报告 + 未读完成 ≤ CompletionDepth。SUBMIT预留，POP归还；REPORT保持至完成握手。
  • 必须协调复位Tile、Pool、Fabric及DDR在途事务，或先quiesce；generation不能撤销已发DDR写入。独立热复位不支持。
  • 软件超时不取消Job，不得立即复用buffer或强行释放Engine。
  • 原版Backend仍使用NO_ERROR_HANDLING；Engine监测整个ND Job的AXI R/B真实握手RESP[1]，锁存首个错误至最终完成。同周期读写错误优先读错误。正常排空，无retry/abort；错误目标数据不可使用。
  • 硬件检查共享DDR范围和源/目的重叠，不提供per-Tile安全隔离。

总主端口数

DDR Fabric 至少接受 NumMasters = NumTiles + NumDmas 条逻辑 AXI Master。举例 4 Tile + 2 DMA = 6 路，各自带 AR/R/AW/W/B 五通道。Global Xbar 负责 AXI 仲裁、传输 ID 扩展和响应路由；不能用简单 MUX 代替。

问题建议
AXI 地址/数据/ID 类型保证 Cheshire 的 `axi_ext_llc_*` 和 DMA 的 AXI Master 数据宽度/ID 兼容；必要时插入 width/id converter

私有 SRAM当前只允许全局 DDR；若要 DMA 访问 Tile 私有 SRAM，另设计入站访问/地址隔离/权限，不属于本版

14 / SOFTWARE

CPU 提交一次 DDR→DDR Job：裸机软件草案

以下示例使用方案 B2 建议的 Pool MMIO，不是原始 idma_reg64_2d 的现成驱动。每个 Tile 的 CPU 都使用同一个数值 DMA_BASE，因为输出端口物理独立。

c#include <stdint.h>
#define DMA_BASE           0x01000000UL
#define REG_CONF           0x000
#define REG_DST_LO         0x0D0
#define REG_DST_HI         0x0D4
#define REG_SRC_LO         0x0D8
#define REG_SRC_HI         0x0DC
#define REG_LEN_LO         0x0E0
#define REG_LEN_HI         0x0E4
#define REG_DSTRIDE_LO     0x0E8
#define REG_DSTRIDE_HI     0x0EC
#define REG_SSTRIDE_LO     0x0F0
#define REG_SSTRIDE_HI     0x0F4
#define REG_REPS_LO        0x0F8
#define REG_REPS_HI        0x0FC
#define REG_POOL_SUBMIT    0x100  // 新增，而非原版 iDMA
#define REG_COMP_VALID     0x108
#define REG_COMP_JOB_ID    0x10C
#define REG_COMP_STATUS    0x110
#define REG_COMP_POP       0x114
#define REG_LAST_JOB_ID    0x11C
#define REG_Q_STATUS       0x104
#define REG_SUBMIT_STATUS  0x120

static inline void wr(uint32_t off, uint32_t v) {
  *(volatile uint32_t *)(DMA_BASE + off) = v;
}
static inline uint32_t rd(uint32_t off) {
  return *(volatile uint32_t *)(DMA_BASE + off);
}
static inline void wr64(uint32_t off, uint64_t val) {
  wr(off,   (uint32_t)val);
  wr(off+4, (uint32_t)(val >> 32));
}

uint32_t submit_ddr_copy(uint64_t src, uint64_t dst, uint32_t len) {
  // 此短例只支持默认DDR窗口，0表示失败；正式代码使用shared_dma_try_submit。
  if (!len || src >= 0x100000000ULL || dst >= 0x100000000ULL ||
      src < 0x80000000ULL || dst < 0x80000000ULL ||
      len > 0x100000000ULL-src || len > 0x100000000ULL-dst ||
      (src < dst+len && dst < src+len)) return 0;
  if (!(rd(REG_Q_STATUS) & 1)) return 0;
  wr64(REG_SRC_LO, src);
  wr64(REG_DST_LO, dst);
  wr(REG_LEN_LO, len); wr(REG_LEN_HI, 0);
  wr64(REG_SSTRIDE_LO, len);
  wr64(REG_DSTRIDE_LO, len);
  wr(REG_REPS_LO, 1); wr(REG_REPS_HI, 0);
  wr(REG_CONF, 1u << 10);   // 2D 前端，REPS=1 → 1 次 1D
  __asm__ volatile ("fence iorw, iorw" ::: "memory");
  wr(REG_POOL_SUBMIT, 1);   // 仅这一次新的外层提交；不再配置 Backend MMIO
  __asm__ volatile ("fence iorw, iorw" ::: "memory");
  if (rd(REG_SUBMIT_STATUS)) return 0;
  return rd(REG_LAST_JOB_ID);
}

// 示例：读完成队首，不对 NEXT_ID 做任何副作用读取
int poll_completion(uint32_t job_id) {
  for (uint32_t n = 0; n < 1000000; n++) {
    if (!rd(REG_COMP_VALID)) continue;
    uint32_t completed = rd(REG_COMP_JOB_ID);
    uint32_t status    = rd(REG_COMP_STATUS);
    wr(REG_COMP_POP, 1);
    if (completed == job_id) return status ? -2 : 0;
    // 多 Job 应用应存储其他 Job 的完成事件，避免误丢。
  }
  return -1;
}
正式驱动：sw/include/shared_dma.h提供shared_dma_try_submit(base, job, mem_start, mem_end, addr_width, id)及shared_dma_poll。返回0成功、-1容量不足、-2非法；地址窗口和位宽须匹配硬件。上面短例返回0失败且不能区分ID回绕，仅解释MMIO流程。正式应用须保留其他Job事件，不得像简单轮询样例一样丢弃；须完成source clean、dirty destination clean及完成后destination invalidate。fence不替代cache维护。

17 / COMPARISON

与“完整原始 DMA + Programmer”方案对比

特征方案 A：两级 MMIO + 原始完整 DMA方案 B：一次 MMIO + 直接 ND Job
CPU 配置外层 CSR有有
Scheduler 到 Engine硬件再对原始 DMA 执行 10+ MMIO 写/读直接传送 `idma_nd_req_t`；无第二级 MMIO
执行端寄存器 Frontend每个原始 DMA 保留M 个执行 Engine 无重复 Frontend
原始 Midend / Backend原样原样
提交控制延迟额外的 AXI MMIO 编程状态机直接硬件 valid/ready
新增复杂性M 个 AXI Programmer + 任务跟踪ND Holding/完成跟踪/CSR 转换
小 Job 吞吐较易被二次配置限制通常更合适
硬件模块封装侵入度最低需要重组 `cheshire_idma_wrap` 功能边界

决策：把 Scheduler 对 Engine 的接口固定为完整 tagged_job_t + Completion。方案 B 直接对 ND Midend 输入，后端不需要任何二次 MMIO。这样即使未来换 Engine 实现，也不用重写 CPU CSR 与 Scheduler。
