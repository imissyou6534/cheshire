2. SoC 总体架构

源码确认：hw/cheshire_soc.sv 是 SoC 顶层；target/xilinx/src/cheshire_top_xilinx.sv 是 VCU118/VCU128/Genesys2 板级顶层。CVA6、Debug、DMA、Ara、FFT、VGA、USB 等作为 AXI master 或 slave 接入主 AXI crossbar；UART/SPI/I2C/GPIO/CLINT/PLIC 等普通控制外设位于 AXI-to-Reg 后面的 Regbus demux。

AXI Master

CVA6 core、Debug SBA、Ara、FFT、DMA、VGA、USB、Serial Link RX、external AXI master。

AXI Slave

Debug Module AXI slave、Reg demux window、LLC/SPM/DRAM path、DMA config、Serial Link TX、external AXI slave。

Regbus Slave

Boot ROM、CLINT、PLIC、SoC regs、LLC regs、UART、I2C、SPI、GPIO、VGA cfg、USB cfg、BusErr、CLIC、external reg slave。

CPU 紧耦合加速器

Ara 与 FFT 复用 CVA6 accelerator 接口；Ara 不是 MMIO 外设，FFT 也不是 MMIO 外设。

3. CVA6 + Ara 架构

源码确认：hw/cheshire_pkg.sv: gen_cva6_cfg() 设置 ret.RVV = cfg.Ara | cfg.Fft，同时 ret.CvxifEn = 0。在当前 pin 住的 CVA6 中，core/include/build_config_pkg.sv:23-24,100 用 RVV 派生 EnableAccelerator 和第 5 个写回端口，因此 Ara/FFT 走的是 CVA6 的 accelerator/RVV 路径，不依赖 CvxifEn。

源码确认：Ara 顶层 .bender/git/checkouts/ara-*/hardware/src/ara.sv 暴露 acc_req_i/acc_resp_o 和 AXI master。Cheshire 中 AraDataWideWidth = 32 * Cfg.AraNrLanes；当前 VCU118 和仿真 Ara 配置为 AraNrLanes=2，因此 Ara wide AXI 数据宽度为 64 bit，与 Cheshire AxiDataWidth=64 相同，但代码仍保留 axi_dw_converter。

源码确认：Ara checkout 中 hardware/src/cva6_accel_first_pass_decoder.sv 当前识别普通 RVV 指令，还额外识别 FFT custom 指令：OpcodeCustom0/funct3=101/log2N=12 和 0x0000002b wait 指令。

6. Register Bus 架构

Regbus 是 32-bit 控制总线，挂在 AXI crossbar 的 AxiOut.reg_demux 后面。路径是：

CVA6/Ara/DMA/Debug AXI master
  -> AXI Xbar
  -> AxiOut.reg_demux
  -> axi_riscv_atomics_structs
  -> axi_cut
  -> axi_to_reg_v2
  -> addr_decode(RegMap)
  -> reg_demux
  -> UART/SPI/I2C/GPIO/CLINT/PLIC/...

8. 外设开关方法

不要直接修改 DefaultCfg。推荐写目标专用配置函数，从 DefaultCfg 复制后覆盖需要的字段，再在仿真或 FPGA 顶层选择它。

function automatic cheshire_cfg_t gen_my_cva6_ara_cfg();
  cheshire_cfg_t ret = DefaultCfg;

  ret.Ara        = 1;
  ret.AraNrLanes = 2;
  ret.AraVLEN    = 2048;

  ret.Bootrom    = 1;
  ret.Uart       = 1;
  ret.SpiHost    = 1;
  ret.Gpio       = 1;
  ret.Dma        = 0;
  ret.I2c        = 0;
  ret.SerialLink = 0;
  ret.Vga        = 0;
  ret.Usb        = 0;
  ret.AxiRt      = 0;
  ret.Clic       = 0;
  ret.IrqRouter  = 0;
  ret.BusErr     = 1;

  return ret;
endfunction
RTL feature enable 与 FPGA pin enable 不同：Cfg.I2c=0 会删除 I2C RTL 和地址 rule；没有定义 USE_I2C 只是板级顶层不暴露 I2C pad。若 Cfg.I2c=1 但 USE_I2C 未定义，内部 I2C 仍可能综合，只是 pin 在顶层适配中没有接到外部端口。

10. 地址译码原理

一级 AXI map 在 gen_axi_out() 中生成。它只知道大类：Debug、Regbus window、LLC/SPM/DRAM、DMA config、Serial Link、external AXI slave。普通外设并不是 AXI crossbar 的直接输出，而是共享 AxiOut.reg_demux。

二级 Reg map 在 gen_reg_out() 中生成。它把 0x0200_0000..0x0c00_0000 中的具体窗口分给 BootROM、CLINT、UART、PLIC 等。

为什么 UART 经过两级：CVA6 发 AXI 请求到 0x0300_2000；AXI xbar 看到该地址落在 0x0200_0000..0x0c00_0000，送到 AXI-to-Reg；Regbus addr_decode 再按 0x0300_2000..0x0300_3000 选择 RegOut.uart。

11. 修改外设地址

情况 1：UART 从 0x0300_2000 改到 0x0301_0000

若新地址仍在一级 Regbus window 0x0200_0000..0x0c00_0000 内，只需改二级 Reg map 和软件符号。

// hw/cheshire_pkg.sv, gen_reg_out()
if (cfg.Uart) begin
  i++; ret.uart = i; r++;
  ret.map[r] = '{i, 64'h0301_0000, 64'h0301_1000};
end

同步检查：

  • sw/link/common.ldh: __base_uart
  • 裸机 headers / tests 是否硬编码 UART 地址
  • device tree / OpenSBI / Linux console，如果当前系统使用它们
  • testbench/VIP 是否假设旧 UART 地址
  • 无需改 cheshire_soc.sv，因为实例仍接 reg_out_req[RegOut.uart]

情况 2：UART 移到 0x4000_0000

仅改 gen_reg_out() 不够，因为一级 AXI xbar 默认不会把 0x4000_0000 送到 Regbus。必须让 gen_axi_out() 也有一条规则，把 0x4000_0000..0x4000_1000 路由到 AxiOut.reg_demux。

// 示例思路：一级把新 UART 窗口送到 reg_demux
ret.map[r] = '{1, 64'h4000_0000, 64'h4000_1000}; // idx 1 == reg_demux

// 二级再把同一窗口送到 UART
ret.map[r] = '{ret.uart, 64'h4000_0000, 64'h4000_1000};
若地址落入 CVA6 external on-chip 或 DRAM 属性区，还要检查 gen_cva6_cfg() 中 NonIdempotent/Execute/Cached region，避免 MMIO 被错误 cache 或 speculative access。

12. 修改 DRAM/SPM 地址

DRAM 从 0x8000_0000 改到 0x4000_0000

硬件入口是 Cfg.LlcOutRegionStart 和 Cfg.LlcOutRegionEnd。它们同时影响 gen_axi_out() 的 AXI map 和 gen_cva6_cfg() 的 executable/cacheable region。

ret.LlcOutRegionStart = 64'h4000_0000;
ret.LlcOutRegionEnd   = 64'h8000_0000; // 示例，大小自行规划

必须同步检查：sw/link/common.ldh 的 dram origin、OpenSBI payload 地址、Linux DTS memory node、bootloader preload、testbench DRAM model、CVA6 cached/executable attributes、PMP/boot ROM 是否假设旧 DRAM。

SPM 地址修改

SPM 基址由 AmSpm = 0x1000_0000 控制，uncached alias 用 AmSpm + 0x0400_0000。大小由 get_llc_size(Cfg) 计算，当前默认 8 * 256 * 8 * 64 / 8 = 131072 bytes。

改 SPM 时同步检查：AmSpm、AmSpmBaseUncached、AmSpmRegionMask、sw/link/common.ldh 的 spm、boot ROM stack、FFT tests 中 SPM_UNCACHED_ALIAS、CVA6 cacheable/executable region。

13. 新增 Reg 外设

推荐方案 A：External Reg Slave

新增 my_timer，地址 0x0300_A000，4 KiB，一个 interrupt。优先使用 external reg slave，避免侵入 Cheshire core。

function automatic cheshire_cfg_t gen_my_cfg();
  cheshire_cfg_t ret = DefaultCfg;
  ret.RegExtNumSlv = 1;
  ret.RegExtNumRules = 1;
  ret.RegExtRegionIdx[0] = 0;
  ret.RegExtRegionStart[0] = 64'h0300_A000;
  ret.RegExtRegionEnd[0]   = 64'h0300_B000;
  ret.NumExtInIntrs = 1;
  return ret;
endfunction

顶层连接：reg_ext_slv_req_o[0]/reg_ext_slv_rsp_i[0] 接 my_timer 的 Regbus 端口；intr_ext_i[0] 接 timer IRQ。因为 gen_axi_out() 会把 external reg rules 也追加到一级 AXI map 并指向 reg_demux，所以 CPU/Ara/DMA/Debug 都能通过 AXI-to-Reg 访问它。

方案 B：做成 Cheshire 内建外设

需要修改源文件，本文不执行。流程：

  • hw/cheshire_pkg.sv: cheshire_cfg_t 加 bit MyTimer，DefaultCfg 设默认，reg_out_t 加 index，gen_reg_out() 加地址 rule。
  • hw/cheshire_soc.sv: if (Cfg.MyTimer) 实例化 my_timer，连接 reg_out_req[RegOut.my_timer] 和 IRQ。
  • Bender.yml: 加 RTL source。
  • hw/regs/cheshire_regs.hjson: 如需 feature detection，加 hw_features.my_timer 并重新运行 regtool。

14. 新增 AXI Slave

新增 1 MiB SRAM：0x4000_0000..0x4010_0000。推荐用 external AXI slave。

ret.AxiExtNumSlv = 1;
ret.AxiExtNumRules = 1;
ret.AxiExtRegionIdx[0] = 0;
ret.AxiExtRegionStart[0] = 64'h4000_0000;
ret.AxiExtRegionEnd[0]   = 64'h4010_0000;

连接 axi_ext_slv_req_o[0]/axi_ext_slv_rsp_i[0] 到 SRAM AXI slave。由于 AXI xbar connectivity 是全连接，CPU、Ara、FFT、DMA、Debug SBA 等 AXI managers 都可访问该 slave，除非你在 wrapper 额外限制。

Cacheability 不是 external AXI rule 自动决定的。若 SRAM 希望 cacheable/executable，必须检查 gen_cva6_cfg() 中 external on-chip CIE 切分或新增 CVA6 region 属性；否则按 non-idempotent/MMIO 处理。

15. 新增 AXI Master

推荐架构：CPU 通过 RegExt slave 控制 accelerator，accelerator 通过 AxiExt master 主动访问 DDR/SPM/SRAM，并通过 NumExtInIntrs 回报完成/错误。

ret.RegExtNumSlv = 1;
ret.RegExtNumRules = 1;
ret.RegExtRegionIdx[0] = 0;
ret.RegExtRegionStart[0] = 64'h0300_A000;
ret.RegExtRegionEnd[0]   = 64'h0300_B000;

ret.AxiExtNumMst = 1;
ret.NumExtInIntrs = 1;

连接关系：

reg_ext_slv_req_o[0] -> accelerator CSR regbus
accelerator CSR rsp  -> reg_ext_slv_rsp_i[0]
accelerator axi_req  -> axi_ext_mst_req_i[0]
axi_ext_mst_rsp_o[0] -> accelerator axi_rsp
accelerator irq      -> intr_ext_i[0]
普通 external AXI master 不天然与 CVA6 D-cache coherent。Ara 在 Cheshire 内部使用 axi_inval_filter 给 CVA6 L1D 发 invalidation；外部 NPU/FFT 若与 CPU 共享 cacheable DDR buffer，软件通常需要 flush/invalidate/fence，或硬件增加一致性/失效机制。

16. 中断系统

cheshire_int_intr_t 包含 bus_err、gpio[31:0]、usb、SPI、I2C 多路、uart 和 zero。NumExtInIntrs 增加外部 interrupt source，先经过同步器进入 intr.ext，再进入 PLIC/CLIC/IRQ router fanout。

新增外设若使用 External Reg Slave，推荐用 intr_ext_i 作为外部中断输入；若做成内建外设，则需要扩展 cheshire_int_intr_t 和中断控制器配置，侵入更大。

20. Ara 特殊配置

源码确认：gen_cva6_cfg() 中 ret.RVV = cfg.Ara | cfg.Fft。CVA6 build_config_pkg.sv 中 EnableAccelerator = CVA6Cfg.RVV，因此当 Cfg.Ara=1 或 Cfg.Fft=1 时，CVA6 accelerator 通路应启用。

源码确认：ret.CvxifEn = 0。在当前 CVA6 版本中，这并不关闭 RVV/Ara accelerator 通路；它关闭的是另一套 CV-X-IF FU 路径。需要在 elaboration 中打印/检查 CVA6Cfg.RVV 和 CVA6Cfg.EnableAccelerator 最终值。

Ara 访存路径：RVV instruction -> CVA6 first pass decoder -> ACCEL scoreboard entry -> CVA6 accelerator interface -> Ara dispatcher -> sequencer/lane/VLSU -> Ara AXI -> invalidation filter -> width converter -> Cheshire AXI xbar -> LLC/SPM/DRAM。

MMU 路径：Ara 通过 acc_mmu_req/acc_mmu_resp 使用 CVA6 LSU 中的 accelerator MMU arbitration。FFT 当前在 multi_accel_router 中关闭 fft_req_o.acc_mmu_en 并清零 MMU response，因此 FFT 使用传入物理/系统地址，不走 Ara MMU 翻译路径。

22. 推荐最小 CVA6 + Ara SoC

用于研究 CVA6 + Ara 时，建议保留 BootROM、UART、SPI Host、CLINT、PLIC、LLC/SPM、DDR、BusErr；关闭 I2C、DMA、SerialLink、VGA、USB、AXI RT、CLIC、IRQ Router。GPIO 可按板级调试需要保留或关闭。

function automatic cheshire_cfg_t gen_min_cva6_ara_cfg();
  cheshire_cfg_t ret = DefaultCfg;
  ret.Ara = 1;
  ret.AraNrLanes = 2;
  ret.AraVLEN = 2048;
  ret.I2c = 0;
  ret.Dma = 0;
  ret.SerialLink = 0;
  ret.Vga = 0;
  ret.Usb = 0;
  ret.AxiRt = 0;
  ret.Clic = 0;
  ret.IrqRouter = 0;
  return ret;
endfunction

精简后保留地址：Debug、BootROM、CLINT、SoC regs、LLC regs、UART、SPI、GPIO(若保留)、BusErr、PLIC、SPM cached/uncached、DRAM。

24. Bring-up / 验证流程

编译/elaboration 验证

  • 打印或查看 Cfg.Uart/I2c/Ara/Fft/Dma。
  • 检查 AxiIn.num_in、AxiOut.num_out、RegOut.num_out 是否符合预期。
  • 检查 CVA6Cfg.RVV 和 CVA6Cfg.EnableAccelerator。

地址验证

  • 对每个 MMIO base 读写一个安全寄存器。
  • 关闭的外设访问旧地址应得到 decode/error response 或 Reg error slave，不应静默访问其他设备。
  • 验证 DRAM/SPM cached/uncached alias 的读写一致性。

Ara 验证

  1. vsetvli
  2. vector ALU
  3. vector load
  4. vector store
  5. Ara store 后 CVA6 scalar load，观察 invalidation/fence 行为
  6. 跨页 vector load/store，观察 acc_mmu_req/resp

FPGA 验证

综合报告中检查关闭的 UART/I2C/VGA/USB/DMA 是否减少 LUT/FF/BRAM；同时确认相关 top-level pin 被移除或 tie-off。只关闭 USE_* pin 宏不足以证明 RTL 被裁剪。

25. 开发 Checklist

  • 先决定使用内建修改还是 External Reg/AXI 扩展；默认优先 external。
  • 任何 MMIO 地址改动同时检查一级 AXI map 和二级 Reg map。
  • 任何 DRAM/SPM 改动同时检查 CVA6 memory attributes 和软件 linker/DTS。
  • 任何新增 AXI master 都制定 cache flush/invalidate 或硬件一致性策略。
  • Ara/FFT 打开后确认 first pass decoder、CVA6Cfg.RVV、EnableAccelerator。
  • FPGA 资源裁剪以 Cfg.* 为准，board pin 宏只负责端口暴露。
  • 修改 HJSON 后重新运行 regtool，并同步软件 generated headers。
  • 验证关闭设备旧地址不会误路由到其他设备。
