## Limits And Future Updates

The isolated resolver used temporary Git URL rewrites to seed its own database
from the existing prepared repositories; no such transport rewrites or local
paths are committed in the project configuration. Remote branch heads were
verified independently. This proves the selected graph and version consistency,
not a clean network bootstrap from GitHub.

No full simulation, synthesis or FPGA programming was rerun for this metadata
migration. Generated artifacts, `.generated` markers, software submodules,
external models and toolchains still require a separate fresh-environment
provisioning procedure. Existing object files and debug backups remain local.

For future IP work, commit and push the IP first. Then update its full SHA in
both root manifests, resolve the lock in an isolated directory with other
packages frozen, and validate before updating a working build environment.
Do not run raw `bender update`, `checkout`, or cleanup commands in the protected
active tree. Retain the historical prepared snapshots for recovery reference.
